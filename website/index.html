02 / THE PLATFORM

Context matters.
Boundaries do, too.

The agent chooses relevant tools, reads their results, and reassesses. Local incident memory adds context while runtime checks constrain what the model can request.

06

read-only investigation tools
6 calls by default · up to 12

01Historical incident memory

search_historical_incidents
Retrieve similar ChromaDB cases. Past labels provide context and are not automatically trusted ground truth.

02Related security events

search_related_agent_logs
Query recent Wazuh Indexer alerts for the same monitored agent and the relevant time window.

03Process execution context

inspect_process_tree
Retrieve process-creation and execution evidence, including available parent-process context.

04Network activity

inspect_network_connections
Inspect recorded network connections or firewall evidence for the affected agent.

05Public IP reputation

check_ip_reputation
Use configured providers for an observed, globally routable IP. Private or unobserved addresses are blocked by the investigation policy.

06File-hash reputation

inspect_file_hash
Look up a hash present in the alert or collected evidence. Missing provider results remain unknown.

Local inference first

Ollama is the default runtime. Gemini and external threat-intelligence services are optional integrations.

Checks beyond the prompt

Tool arguments, host scope, and call budgets are validated in code. Report structure is checked before optional case creation.

A trace of the investigation

Tool attempts, result status, model identity, and fallback use make the investigation easier to review.
